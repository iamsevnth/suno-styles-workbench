# Sonic Planner & Attribute Roles

## 6.1 Seeded PRNG Architecture (mulberry32 & hashString)
Suno Workbench eliminates non-reproducible randomness by routing every sampling operation
through src/lib/suno/rng.ts. When you click Compile without a manual seed lock, generate.ts
derives a 32-bit unsigned seed via ((Math.random() * 0xffffffff) >>> 0) ^ (Date.now() & 0xffffffff).
When you lock a numeric seed or re-run a historical card, mulberry32(seed) produces an identical
sequence of floating-point values in [0, 1), ensuring 100% deterministic reproducibility across
browsers and operating systems.

     TypeScript Implementation — Seeded PRNG Engine (src/lib/suno/rng.ts)
     export function mulberry32(seed: number): () => number {
         let a = seed >>> 0;
         return function () {
             a |= 0;
             a = (a + 0x6d2b79f5) | 0;
             let t = Math.imul(a ^ (a >>> 15), 1 | a);
             t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
             return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
         };
     }


     export function hashString(str: string): number {
         let h = 2166136261 >>> 0;
         for (let i = 0; i < str.length; i++) {
             h ^= str.charCodeAt(i);
             h = Math.imul(h, 16777619);
         }
         return h >>> 0;
     }




## 6.2 The 3-Variant Structural Role Rotation (buildPlans)

when a producer knows the exact three genres they want to fuse—for example, Future Bass,
Aggressive Trap, and 140 UKG—which genre serves as the rhythmic spine versus the harmonic



bed versus the drop accent completely changes the resulting song. In src/lib/suno/plan.ts,
buildPlans() constructs three orthogonal SonicPlan blueprints from the same parsed input:

## 6.4 Attribute Provenance Tracking (User vs. Locked vs. Inferred)
Every SonicPlan carries a Provenance map (Record<string, AttributeSource>) that tags each axis
as 'user' (explicitly typed in your brief), 'locked' (forced via a UI Lock control), or 'inferred'
(synthesized by the compiler from ontology.ts, profile.ts, and lexicon.ts). This provenance map is
rendered directly on each Variant Card so you can audit how your brief was interpreted and
decide which axis to lock on your next iteration.
