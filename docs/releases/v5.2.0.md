# Suno Workbench v5.2.0 — Source-Preserving Lyrics Studio

Version 5.2 replaces the visible legacy lyric-creation workflow with a source-preserving song arrangement workspace.

## What's changed

- **Two input modes:** paste an entire draft with recognizable section tags, or paste into individually typed original source sections. A change of input mode transfers existing material to the other mode.
- **Custom song structure:** suggest destination sections or add/reorder/remove them, select the source, and set 1–64 planned bar slots and either original lines or phrase chopping.
- **No invented lyric words:** each output phrase is an exact substring from a source line, with a source section ID, source line number, character offsets, and repetition metadata. Output is validated and read-only; any source/configuration change invalidates earlier results.
- **Rhythm/rhyme assistance:** optional approximate rhyme-group retention (AABB/ABAB and adjacent endings), a crude text syllable estimator, target BPM with optional original BPM, and cautionary delivery warnings. Estimates are not audio analysis.
- **Reproducible variation:** seeded, constraint-aware shuffling of existing lyric phrases, with conservative treatment of locked source sections.
- **Local project recovery:** explicit browser save/restore/clear, versioned validated JSON project import/export, Suno-ready TXT export and clipboard copy.
- **American Phonetics Converter:** remains accessible as before; users may transfer rearranged lyrics to it.
- **No new dependencies, remote AI, accounts, backend service or creative-content uploads.** Hosted and self-contained offline editions remain available.

## Limitations

- A lyric line or fragment is treated as one **planned bar slot**. This is not a validated correspondence to a performed musical bar.
- Extending a 16-slot chorus to an 8-slot buildup plus a 16-slot drop necessarily repeats or subdivides the submitted words. Original melodies, harmonies, drum parts and timing are not analyzed.
- Rhyme and syllable results are rough spelling-based estimates; the tool cannot guarantee actual rhyme, cadence, stressed syllables, rap flow, or Suno's interpretation.
- Locking conservatively preserves original source-line order when a destination pool includes any locked source.
- Local saving is opt-in and scoped to the current browser profile. Keep exported JSON backups; clearing site data removes the saved copy.
- The old deterministic lyric generator remains present for historical test compatibility but no longer appears as an active Lyrics Studio action.

## Validation criteria

Run `npm run lint`, `npm test`, `npm run build`, and the existing dependency review, CodeQL, and README Score workflows. New tests must cover source provenance, tampering, 16-to-24-slot reuse, deterministic variations, long-line chopping, recognizable rhyme groups, source locks, invalid targets, and JSON import validation. Production deploy must be verified against the final merged SHA.

## Future

Browser-local ML ranking, phonetic-dictionary rhyme analysis, and more accurate tempo/meter analysis remain exploratory and are not prerequisites for v5.2. The evidence-backed Prompt Fidelity Inspector is deferred to a later release.
