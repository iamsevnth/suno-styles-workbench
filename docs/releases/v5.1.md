# Suno Workbench v5.1

Suno Workbench v5.1 builds on the 29 native genre banks introduced in v5.0, with more precise reading of musical briefs, source-preserving Fix mode, and new ways to explore meaningful production differences. The compiler now treats negative constraints separately from positive directions, exposes native-bank Sonic Identity focuses, and offers a controlled two-prompt A/B comparison. The browser-only, offline-capable architecture remains unchanged: no application backend, LLM, or external processing API is required.

## Highlights

- **800–975-character Styles target** across native and legacy renderers, while retaining the **1,000-character hard cap**.
- **Precision parsing** for musical keys and accidentals, scale modes, meter, BPM ranges, and target versus reference or perceived tempos.
- **Separate Suno Exclude field** with copyable prohibitions and a hard gate against reintroducing excluded wording into Styles.
- **Source-preserving Fix mode** that retains coherent source instructions, conservatively compresses or expands where possible, and falls back to recompilation when preservation cannot safely fit.
- **Sonic Identity focuses inside the existing 29 native banks**—not a competing genre catalog—emphasizing bass, drums, sound design, or arrangement using bank-compatible phrases.
- **Semantic variation checks** that compare actual musical decisions, not arbitrary changes to the title, seed, or recipe identifier.
- **Controlled A/B Lab** that creates two prompts changing one bass-articulation phrase while holding the other musical choices constant.
- **415 automated tests passed**, along with TypeScript, dependency review, and the offline/production build.

## More Precise Musical Intent

The parser keeps musical metadata and descriptive constraints structured rather than relying on the last incidental keyword.

- **Tempo:** Distinguishes target BPM, ranges, source/reference BPM, and perceived half-time/double-time feel. A range is resolved to a single generation BPM within the supported compiler range.
- **Key and mode:** Recognizes accidentals written as symbols or words, including sharp and flat spellings, alongside major, minor, and supported modal names.
- **Meter:** Carries explicitly named time signatures into the musical plan and Styles lead where appropriate.
- **Arrangements:** Captures selected Drop 2, silence/fakeout, motif, and bar-count cues for safer retention through the compiler.
- **Instrumental versus vocal intent:** Distinguishes an instrumental answer or vocal-chop effect from an instruction to add a lead singer.

The original first-named genre and v5 native routing rules remain in control of the arrangement.

## Exclusions Stay Separate From the Styles Prompt

Negative instructions are now handled as constraints instead of mistakenly becoming production suggestions.

- **Negation-aware extraction:** Identifies prohibited sounds or techniques, including comma-separated exclusions.
- **Copyable Exclude:** Displays excluded concepts in a dedicated field for Suno Custom Mode.
- **Hard validation:** Flags output that reintroduces an excluded phrase into positive Styles wording.
- **No inversion:** The compiler no longer repairs phrases such as “exclude” by turning them into an instruction to “favor” the same sound.
- **Genre protection:** The existing native genre-bleed restrictions remain active, including the native phonk exceptions already established in v5.0.

Explicit requested genres, instruments, and vocal descriptions are not meant to be discarded merely because they appear near an exclusion.

## Fix Existing Prompt: Preserve Before Rebuilding

Fix mode now prefers the user's existing musical directions when they are sufficiently coherent and can be safely fitted to the character window.

- **Preservation first:** Keeps well-formed source passages rather than regenerating every musical clause.
- **Conservative editing:** Makes limited syntactic compression or adds compatible, already-planned production details to short but valid prompts.
- **Key consistency:** Recognizes equivalent spellings such as C-sharp and C# without inserting a duplicate key instruction.
- **Structured details:** Improves handling of existing vocal registers, motifs, Drop 2 changes, silence cues, and section lengths.
- **Clear fallback:** Recompiles the prompt when preserving it would exceed the target, violate a hard gate, or require dropping important information without a safe edit.
- **Visible outcome:** Prompt cards identify whether Fix preserved, compressed, expanded, or recompiled the source.

Because Fix can still fall back to recompilation, review the generated output for important section-specific details before using it.

## Native Sonic Identity Expansion

Sonic Identity now describes *how* the chosen native genre behaves, rather than substituting a different genre or an unrelated vocabulary bank.

- **29 existing native banks retained:** Each bank continues to determine its own rhythm, sound palette, tempo conventions, and genre restrictions.
- **Four focus directions:** Bass articulation, drum/rhythmic behavior, sound design and textures, or arrangement structure.
- **Native phrase ownership:** Focus variations select compatible phrases from the active genre bank and respect the brief's named directions.
- **Genre fidelity:** Existing genre-bleed and exclusion filters apply before a phrase can be used.
- **Precision and Exploration:** Precision emphasizes the original brief; Exploration changes which native production focus receives attention.

This adds musical choices without replacing the bass/club/rap generator introduced in v5.0.

## Semantic Variation: Musical Differences, Not Just New Wording

The variation validator compares actual production decisions across generated candidates.

- **Rhythm:** Drum signatures and groove architecture.
- **Bass:** Bass topology, articulation, or principal bass design.
- **Sound design:** Character and texture of the sound palette.
- **Arrangement:** Structural decisions and section development.
- **Vocals:** Vocal presence and delivery architecture.

Title changes, differing random seeds, and recipe IDs do **not** count as musical variation by themselves. Standard variants must demonstrate differences across meaningful production axes.

## A/B Lab: One Variable at a Time

A/B Lab provides a controlled two-prompt comparison rather than two independently rebuilt prompts.

- **Two outputs:** The second starts from the first validated production plan.
- **Bass articulation only:** One compatible bass phrase is replaced using the same native bank.
- **Everything else held constant:** Groove, sound-design context, arrangement, vocal direction, selected genre, and BPM are preserved.
- **Surgical Styles edit:** The second output changes only that one rendered bass phrase, avoiding unrelated renderer changes.
- **Full hard-gate checks:** Both outputs must pass the existing character, exclusion, genre-bleed, and coherence checks.
- **Unsupported alternatives:** If no compatible replacement passes those gates, the app reports that a safe A/B pair could not be generated instead of silently changing additional variables.

A/B produces controlled **text differences**; the audible outcome still depends on Suno's generation.

## Compatibility, Privacy, and Offline Use

v5.1 is an additive minor release.

- The native bass, club, and rap banks remain the source of genre-specific production language.
- Draft, Rewrite, and unclaimed-genre behavior remain on their established legacy compiler route, with the improved parsing and Fix safeguards where applicable.
- The requested Styles target is now **800–975 characters**, with an unchanged **1,000-character hard cap**.
- The Guide, Lyrics Studio, and American-English phonetic workflows remain available.
- Prompts and lyrics are processed locally in the browser; there is no server-side compiler or LLM/API processing.
- The application continues to build as a self-contained offline HTML edition.

## Verification

The release candidate was validated against the committed GitHub source:

- **415/415 automated tests passed**, with TypeScript checking, dependency review, site build, and offline/CSP build successful.
- **29/29 native genre banks** passed a deterministic controlled A/B sweep (two outputs per bank), including the one-bass-axis contract and output hard gates.
- **223/223 archived prompt outputs** passed the compiler hard gates during a private Fix-mode benchmark; the underlying private prompt bodies were not committed.
- In that benchmark, **213/223** sources used preservation or conservative editing, while **10/223** required full recompilation.

These checks validate deterministic compiler behavior and text-level retention; they do not establish that every musical instruction survives recompilation or that two generated audio recordings will sound different.

## Known Limitations

- **Complex Fix fallbacks:** Some longer or structurally dense source prompts must still be recompiled. A subset of these can lose vocal traits, motif progression, silence cues, or detailed section instructions despite passing compiler hard gates. Review important source-to-output details.
- **A/B availability:** A compatible bass-articulation alternative is not guaranteed for every combination of exclusions and input details.
- **Audible variation:** Representative Suno listening tests have not been completed as a release-wide certification; text-based musical diversity is not a guarantee of audible contrast.
- **Dancehall:** The previously documented `bass_music_phrasing` validation issue may still affect Dancehall briefs; this release does not claim to fix it.
