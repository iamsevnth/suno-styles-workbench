# Suno Workbench v5.3.2 — Accessibility, Accurate Copy and Browser Tests

v5.3.2 is a maintenance patch on top of v5.3.1. It does not change Styles generation, the Prompt Fidelity Inspector rules, Lyrics Studio arrangement, the privacy model or network behavior.

## Fixed

- **Accessibility (WCAG 2.1 A/AA, found by the new automated scans):**
  - Home page: the "what you get" list is valid description-list markup, so screen readers read each item and its explanation together.
  - Studio tabs: the count badge no longer uses reduced opacity, which had dropped its text below the 4.5:1 contrast minimum.
  - Guide: the chapter list's `aria-controls` points only at panels that exist, and each chapter title is a real level-2 heading under the page heading.
- **Accurate descriptions of Lyrics Studio and the app:** page descriptions, the Home page and the Studio deck no longer say Lyrics Studio writes or "builds" lyrics; it arranges lyrics you supply without adding words. The Home page no longer promises that Variety Off makes Suno use the Styles text "word for word", and the "keeps your words" promise now points to the Prompt Fidelity Inspector, which shows anything that did not carry over.
- **Guide and README** are updated for this release, including the Variation Strategy (Precision, Exploration, A/B Lab) and Hybrid Bass Profile controls that the README did not describe.

## Added (developer-facing, no new UI)

- **Browser tests** (`npm run test:browser`): every page of the built site and the offline file opened from disk, in desktop and mobile Chromium, checked for console errors, requests to other origins and axe WCAG 2.1 A/AA violations, plus one Styles Compiler and one Lyrics Studio workflow. CI runs them before deploying.
- **Experiment Project schema v1** (`src/lib/experiments/`): the validated file format and local storage for the planned v5.4 experiment workflow, with fixtures and tests. There is no user interface for it in this release. Timestamps must be real calendar dates, and saved experiments sort by actual time.
- **Release automation:** the official-release workflow reads the version from `package.json`, so each new version is published once, from the validated `main` commit, without editing the workflow. Existing releases are never overwritten, and a leftover draft release stops the run with a message.
- Tooling: CodeQL Action, Vite and Tailwind updates.

## Official v5.3.2 Download Package

The GitHub Release uses tag **`v5.3.2`** and title **`suno-workbench-sevnthlabs-v5.3.2`**.

- **`suno-workbench-sevnthlabs-v5.3.2.html`** — the complete self-contained offline edition, rebuilt from the validated `main` commit.
- **`suno-workbench-sevnthlabs-v5.3.2.html.sha256`** — SHA-256 checksum for the HTML.

**How to use:** download the `.html` asset from [GitHub Releases](https://github.com/iamsevnth/suno-styles-workbench/releases/tag/v5.3.2), save it, and open it in a modern desktop browser.

**Verify integrity (optional):** with both files in one folder, run `sha256sum -c suno-workbench-sevnthlabs-v5.3.2.html.sha256` (Linux) or `shasum -a 256 suno-workbench-sevnthlabs-v5.3.2.html` and compare with the checksum file (macOS).

## Validation

TypeScript checking, the full regression suite (including the Guide, routes and release-packaging contracts), hosted and offline builds, the offline CSP verifier, and the browser and accessibility tests. CodeQL and dependency review run on pull requests.

## Known limitations

Unchanged from v5.3.1: lexical fidelity detection is not semantic or audio evaluation; Lyrics Studio never invents lyric words; Workbench character targets are application rules, not Suno-certified optima.
