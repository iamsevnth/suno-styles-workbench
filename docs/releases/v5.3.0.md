# Suno Workbench v5.3.0 — Prompt Fidelity Inspector

## Overview

Introduces an evidence-bound, browser-only textual **Prompt Fidelity Inspector** directly inside the Styles Compiler. It audits the original creative brief or pre-Fix prompt against each generated/fixed candidate without inventing an arbitrary audio-quality rating.

## Capabilities

- Opens from every Styles result card, with a concise source-check count and a detailed, inspectable findings table.
- Displays the complete original and final Styles texts side-by-side. In Fix Mode, the unmodified original is explicitly identified as the pre-Fix baseline, not a rating. Users may optionally paste an earlier **original intent/brief** to evaluate both the pre-Fix text and the fixed output against one shared reference.
- Checks supported explicit facts: target BPM/ranges, key, meter, named genres, specific instruments and modifiers, voice/groove/arrangement markers, bar counts, scenes/textures and the separate Exclude field.
- Labels each finding Text Matched, Explicit Difference, Not Detected, or Review Needed; source snippets, output snippets and an explanation are shown for each finding.
- Exports findings as local JSON containing original/final/Exclude texts, transparent rules and links to official Suno control documentation.
- Keeps the legacy internal compiler selection score separate from the inspector. Neither score nor source-check counts predict audio performance.

## Source policy

Official Suno Help documents the separate Exclude feature, the Styles and lyrics controls, Creative Sliders and v6 Variety. These documents do **not** establish objective prompt-quality weights, musical fidelity probabilities, or an optimal Styles character count. The inspector therefore deliberately abstains from such claims.

Methodology and evidence: [Prompt Fidelity Inspector Methodology](../PROMPT_FIDELITY_METHODOLOGY.md).

## Validation

- Existing full-suite regression tests plus new tests in `tests/fidelity.test.ts`, including negative cases and explicitly contradictory target BPM values.
- TypeScript compilation, hosted and offline bundles, CSP verification, dependency review, CodeQL, README Score.
- No change to Lyrics Studio, production prompt generation algorithms, data persistence, API calls, network architecture, or hosting model.

## Known limitations

Lexical detection is not semantic interpretation; an undetected fact may have been paraphrased. Exact matching of source words does not guarantee that Suno will render an audible feature. Source-fact counts are based on supported detectors and are not percentages of all user intent. Reports are text-only and do not process audio.

## Official v5.3 Download Package

The official GitHub Release uses tag **`v5.3.0`** (matching the application package version) and title **`suno-workbench-sevnthlabs-v5.3`**.

Release download assets:

- **`suno-workbench-sevnthlabs-v5.3.html`** — the complete self-contained, offline-capable HTML edition of Suno Workbench v5.3; includes the refreshed searchable Guide, Styles Compiler, Fidelity Inspector, Lyrics Studio, phonetics, and inlined code and styles.
- **`suno-workbench-sevnthlabs-v5.3.html.sha256`** — SHA-256 checksum for verifying the downloaded HTML.

The asset is rebuilt from the same trusted `main` commit as the successful GitHub Pages deployment; the release job reruns TypeScript, all tests, the Vite/site build, and the offline CSP verifier. The release workflow checks package and lockfile versions, Guide files, output size, source/build identity and checksum before uploading. It refuses to overwrite existing release assets on subsequent runs.

**How to use:** Download the `.html` asset from [GitHub Releases](https://github.com/iamsevnth/suno-styles-workbench/releases/tag/v5.3.0), save it locally, and double-click/open it in a modern desktop browser. Workbench's core functionality and Guide work without an application server. External documentation hyperlinks still require internet access.

**Verify integrity (optional):** Place the HTML and `.sha256` in the same folder, then run `sha256sum -c suno-workbench-sevnthlabs-v5.3.html.sha256` (Linux) or `shasum -a 256 suno-workbench-sevnthlabs-v5.3.html` and compare the value with the checksum file (macOS).
