# Suno Workbench v5.5.0 — On-Device AI Rewording (Experimental)

v5.5.0 adds an optional, experimental AI step that **rewords** a prompt the Workbench has already built, using the model Chrome runs on your computer. **The deterministic engine is unchanged:** the same brief, seed and settings produce the same prompts as v5.4.1.

## Added

- **On-Device AI (experimental)** checkbox above the results. It appears only in desktop Chrome versions that include Chrome's built-in AI (the Prompt API with Gemini Nano), and it is off until you turn it on. Other browsers see nothing.
- **Reword on This Device** on each result. The model gets the prompt and an instruction to keep every musical fact (the exact BPM, genres, instruments, vocals, mood) and change only the wording and order.
- **Checks before anything is shown.** The AI wording must pass the same gates as the Workbench's own prompts:
  - length in the Styles window;
  - the exact BPM;
  - no artist names or "in the style of";
  - no negative wording;
  - no lyrics or section tags;
  - no contradictions, genre bleed or excluded concepts;
  - at least as many of the brief's own words as the original.

  Wording that fails is discarded and the reasons are shown; you can try again. Passing wording has its own **Copy AI Wording** button. **Stop** cancels a request.

## Privacy

The Workbench sends nothing to SEVNTHLABS or to any AI service. Chrome runs the model on this computer. The first time a site uses it, Chrome downloads the model from Google; that download and Chrome's handling of the model fall under Google's terms, not SEVNTHLABS's. The Privacy Policy has a new section on this, and the setting is stored in `localStorage`.

## Validation

- 511 unit tests (6 new for the AI gate: accepted rewording, model wrapping removed, negative wording, missing tempo, short text and unchanged copies rejected, instruction contents, no API means unavailable), TypeScript check and production build.
- Browser tests in desktop and mobile Chromium: the option is hidden without the Prompt API; with a stand-in API, valid wording is shown and rule-breaking wording is discarded; axe WCAG 2.1 A/AA scan.
- **Not tested with the real model:** the test machines can't run Gemini Nano, so the browser tests use a stand-in for the API. The gate is what keeps bad wording out, whatever the model returns.
